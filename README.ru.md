# Qingping → ESPHome

[English](README.md) · **Русский**

Единый проект для **Air Monitor Lite, Air Monitor 1 и Air Monitor 2**:
исходники портов, аппаратные профили и общий установщик для Home Assistant.

**Мастер установки пока экспериментальный.** 06.11.2026 выполнен первый полный
цикл через браузер на реальном Lite / CGDN1, stock `4.5.8`, HW `0001`:
Bluetooth setup, локальная передача персонального образа, запуск ESPHome,
подключение к HA и живые CO₂/T/RH. Это подтверждает именно этот аппаратный
профиль. Базовые порты Monitor 1 проверены отдельно; Monitor 2 пока не
поддерживается прошивкой.

## Совместимость

Для Monitor 1 есть отдельное экспериментальное [USB-приложение](apps/monitor1_usb/):
компьютерный WebUSB или USB сервера HA для приватного захвата, профиля и сборки.
На USB сервера добавлена установка stock bridge после явной проверки и
отдельное чтение после загрузки. Готовую сборку можно скачать с компьютерным
ADB-установщиком для macOS/Linux, без локального компилятора и VM. Первая
установка на штатном CGS1 ещё не проверена; запись только из браузера WebUSB
и полный native UI остаются в работе. Обычный допуск HACS в таблице ниже
от этого не меняется.

[Пошаговая инструкция Monitor 1: компьютер или USB сервера HA](apps/monitor1_usb/README.ru.md).

| Прибор | Платформа | Что есть в проекте | Установка через панель |
| --- | --- | --- | --- |
| **Lite / CGDN1**, stock 4.5.8, HW 0001 | ESP32 | UI25, экран, сенсоры, настройки, защищённый API | **Beta**, Bluetooth → локальный MQTT/HTTP |
| **Lite / CGDN1**, stock 4.2.1, HW 0001 | ESP32 + внешний MCU | [Разбор CG/TLV и исследование отдельного порта](ports/lite-mcu421/) | Пока нет образа; мастер объясняет ограничение |

| **Monitor 1 / CGS1**, SCD40, co2_type=3 | Linux ARMv7 | Отдельный драйвер CO₂ и полный интерфейс, проверенные на приборе | Пока исходники; отдельный USB/ADB-путь |
| Monitor 1, SCD30 / неизвестная ревизия | Linux | Требует проверки | Нет |

У Monitor 1 проверен программный reboot; холодное включение и запуск без
доступной Wi-Fi-точки не заявлены проверенными для всех профилей.

## Установить через Marketplace / HACS

1. В Marketplace или HACS откройте **⋮ → Пользовательские репозитории**, добавьте
   `https://github.com/ivaschru/qingping-esphome`, категория **Интеграция**.
2. Откройте Qingping ESPHome и установите последний обычный выпуск (`v0.1.2`
   или новее). Включать показ beta-версий не требуется. Нужен release ZIP:
   исходники без собранного шаблона не содержат образ.
3. Если **Qingping ESPHome** уже настроена в **Устройствах и службах** и панель
   появилась в боковом меню, сразу откройте её — повторно добавлять интеграцию
   не нужно. Если её ещё нет, выберите **Добавить интеграцию → Qingping ESPHome**.
   Локальный адрес и порты выбираются автоматически. Если определить адрес
   не удалось, появится только поле для него. Ручные параметры доступны
   отдельно через **Настроить** у интеграции.
4. Откройте **Qingping ESPHome**, выберите Lite, подключите его к USB и укажите,
   чей Bluetooth использовать: **Этого компьютера / телефона** или **Home Assistant**.
   Первый путь требует Chrome по HTTPS рядом с прибором; второй — адаптера HA
   или активного Bluetooth-прокси рядом с ним. Mi Home не нужен.

Выбор источника Bluetooth доступен в **v0.1.2**. Новый путь через HA проверен тестами
SDK и протокола; полный цикл на реальном приборе ещё предстоит. Ранее описанная
успешная установка выполнена через Bluetooth браузера.

Перезапуск не является обязательным шагом каждой новой установки. Современный
Marketplace умеет обнаруживать новый компонент без него. Если магазин сообщил,
что перезапуск требуется, выполните его: уже загруженный Python-код после
обновления продолжает работать до перезапуска. Подробности — в
[реализации Marketplace Home Assistant 2026.11](https://github.com/home-assistant/core/blob/2026.11.0/homeassistant/components/marketplace/repositories/integration.py).

## Язык и доступ к мастеру

Эти настройки интерфейса доступны в **v0.1.2** и новее.

В мастере есть переключатель **English / Русский**. По умолчанию выбран
английский; выбор сохраняется только в этом браузере. Смена языка не очищает
форму и не прерывает установку. Штатные окна настроек HA используют язык
вашего профиля Home Assistant.

Переключатель **Показывать в боковом меню** есть в **Настройках страницы**
рядом с выбором языка
и в **Устройства и службы → Qingping ESPHome →
Настроить → Интерфейс → Показывать в боковом меню**. Это не останавливает
установщик и не перезапускает активную передачу. Оба переключателя меняют одну
настройку HA: она действует сразу и сохраняется после перезапуска.

Без пункта меню откройте **Устройства и службы → Qingping ESPHome →
устройство установщика → Перейти**. Прямой путь на том же HA:
`/qingping_esphome`. При входе по-прежнему нужны права администратора.

Служебное устройство **Qingping ESPHome** — карточка установщика, а не
физический датчик. Прошитые приборы и их показания находятся в обычной
интеграции **ESPHome**. У прежних версий установщика «0 устройств» нормально.

Home Assistant и датчик должны видеть друг друга в локальной сети. Для HA
Container нужны host networking либо корректные LAN IP и проброс обоих TCP-портов.
Если IP принадлежит хосту вне контейнера, используйте host networking: HTTP
слушатель привязывается именно к указанному адресу. Порты не публикуйте в Интернет.
Обычные порты — MQTT `1886` и HTTP `1887`. При конфликте их можно изменить
в дополнительных настройках. Существующие ручные настройки сохраняются.
**Этого компьютера / телефона** — Web Bluetooth: Chrome по HTTPS на Mac,
Windows или Android. Это устройство должно быть рядом с прибором. Safari,
Firefox и iPhone для этого пути не подходят. Адаптер HA здесь не требуется.

**Home Assistant** — штатная Bluetooth-подсистема HA: локальный адаптер либо
совместимый прокси с **активными GATT-подключениями**, например ESPHome Bluetooth
proxy с включёнными активными подключениями. Доступный адаптер выбирает HA;
прокси, который только слушает объявления, для настройки не подойдёт. Браузеру
Bluetooth и Web Bluetooth не нужны: можно использовать Safari, Firefox, iPhone
или компьютер без Bluetooth. Рядом с прибором должен быть адаптер HA или прокси.
Подробности — в [Bluetooth API HA](https://developers.home-assistant.io/docs/core/bluetooth/api/).

HTTPS требуется для Web Bluetooth в браузерном режиме. Режим HA использует
обычное авторизованное подключение к HA; сохраняйте привычный защищённый
удалённый доступ. Отдельный HTTP-порт используется только прибором,
поэтому SSL-конфигурацию самого HA менять не требуется.

Окно Bluetooth сейчас отбирает приборы с именами, начинающимися на `Qingping`,
`CGDN1` или `Air Monitor`. Поэтому другие устройства поблизости в нём не
показываются. Пустой список сам по себе не доказывает, что Bluetooth не работает:
прибор может быть вне режима подключения или иметь другое объявляемое имя.
Это выбор BLE-устройств, а не общий список спаренных Bluetooth-устройств системы.
[Как работают фильтры Web Bluetooth в Chrome](https://developer.chrome.com/docs/capabilities/bluetooth#name_filter).

## Как проходит установка Lite

Выбранный Bluetooth-путь читает модель, аппаратную версию, stock-версию и MAC.
При выборе через HA соединение после чтения освобождается; перед записью мастер
подключается заново и повторно сверяет весь идентификатор. Выбор действует пять
минут и привязан к выбравшему администратору. Фильтр трёх префиксов имён тот же,
что в браузерном окне выбора.
После команды пользователя передаёт Wi-Fi и временные настройки загрузчика.
Home Assistant независимо сверяет MAC/stock по MQTT и отправляет **одну** OTA
команду. Прибор скачивает персонализированный app по локальному HTTP.

Сборка ESPHome выполняется заранее в GitHub Actions. На HA заменяются только
специально зарезервированные данные публичного шаблона, пересчитываются ESP32
checksum, SHA-256 и CRC Qingping. Для каждого прибора создаются своё имя,
Noise key, пароль OTA и fallback AP. Wi-Fi и ключи не отправляются в GitHub.

Установка считается успешной только после защищённого подключения к новому
ESPHome, совпадения MAC/имени и живых CO₂, температуры и влажности. Затем
интеграция запускает штатное добавление ESPHome в HA; комнату можно выбрать самому.

При тайм-ауте OTA-команда автоматически не повторяется. Намерение и ключи
восстановления сохраняются в приватном HA `.storage/qingping_esphome.installations`
до отправки. Перезапуск HA не запускает повторную прошивку. Сессия передачи
живёт 15 минут; персональный образ держится только в памяти. Держите браузер
открытым во время настройки. Серверная BLE-настройка ограничена по времени и
не повторяется автоматически при обрыве браузера. Сама она не разрешает OTA:
перед продолжением проверяется состояние сессии. До отправки OTA сессию можно закрыть;
после отправки сначала проверьте результат на приборе и в ESPHome.

Замена заводской прошивки может потребовать вскрытия для восстановления при
неудачном раннем запуске. Подключение USB здесь обеспечивает питание: USB data
для Lite не используется. Заводской загрузчик сохраняется; полный backup не
создаётся и сохранность stock после следующих обновлений не гарантируется.

## Обновления прошивки в Home Assistant

Интеграция создаёт стандартную сущность **Прошивка** для каждого проверенного
Lite, установленного её мастером. Новые версии появляются в **Настройки →
Система → Обновления**. Нужен релиз с этой функцией и публичным
`firmware-catalog.json`: изменение исходников само по себе не выпускает прошивку.
Каталог проверяется раз в шесть часов; сущность можно обновить вручную раньше.
Установка начинается по кнопке **Обновить**, которую нажимает администратор.

У прошивки своя версия и номер ревизии внутри аппаратного профиля. Обновление
HACS-интеграции само по себе не создаёт обновление прошивки. Первый backend —
**Lite / CGDN1, direct-I2C, HW 0001, исходная stock 4.5.8**. MCU Lite,
Monitor 1 S8/SCD40 и Monitor 2 требуют отдельных проверенных образов и способов
обновления. Одинаковое название модели не делает образы совместимыми.

Для новых установок HA сохраняет исходные Wi-Fi, резервную точку доступа и
ключи API/OTA в приватном атомарном журнале. Резервные копии HA тоже могут
содержать эти данные — храните их приватно. Обновление скачивает публичный
шаблон из неизменяемого GitHub-релиза, сверяет SHA-256 и манифест и подставляет
настройки внутри HA. Персональные образы и ключи в GitHub не отправляются.
Перед одной зашифрованной передачей app проверяются точные MAC/имя, текущая
версия, USB-питание и настройки. После запуска проверяются сохранение настроек
и повторные реальные CO₂/исходные T/RH. Загрузчик, разметка и NVS не
перезаписываются; автоматического отката и полного бэкапа прошивки нет.

В старых записях установщика Wi-Fi/AP не сохранялись. Перед обновлением
откройте **Qingping ESPHome → Настроить → Подготовить старую установку к
обновлениям**. Введите действующую сеть Wi-Fi и явно задайте резервную точку
доступа для следующей прошивки: её прежний случайный пароль не читается через
обычный API. Ключи API и OTA сохраняются. Сохранение формы не меняет прибор.
Частные и ручные сборки автоматически не принимаются.

Попытка передачи сохраняется до OTA и переживает перезапуск HA. Если
подтверждение потеряно, повторное нажатие **Обновить** только проверяет эту же
попытку без повторной отправки. Оставьте прибор включённым. Если сохранилась
старая версия, сначала нужна проверка результата и отдельное разрешение на
восстановление. Повторные нажатия не снимают эту блокировку.

### Автоматический подхват при переносе между HA

Начиная с интеграции **0.2.0** и прошивки Lite **1**
(build ID **2026.11.07-ui25-profile1**), переносить файл профиля установщика не нужно.
Добавьте прибор в штатную ESPHome-интеграцию нового HA с его прежним ключом
шифрования API. После подключения Qingping ESPHome распознает совместимую
прошивку и автоматически создаст сущность обновления, обычно в течение минуты.
Используются существующие подключение и ключ HA; сброса сети и автоматической
перепрошивки при обнаружении нет.

Прибор отдаёт текущие Wi-Fi, резервную точку доступа и пароль OTA в
зашифрованном ответе только запросившему клиенту. Профиль сохраняется в
приватном журнале HA, без открытых паролей в сенсорах, ответах действий,
браузерном хранилище или GitHub. Перед обновлением он читается заново, чтобы
сохранить изменения Wi-Fi с экрана прибора. Установку запускает администратор
кнопкой **Обновить**, с проверками USB, прибора и настроек. Новый HA не может
сам узнать неизвестный ему ключ: штатное подключение ESPHome с ключом остаётся
отдельным шагом.

Старые прошивки не умеют отдавать профиль. Их нужно один раз обновить, пока
исходный HA ещё хранит профиль обновления, либо подготовить старую установку
по инструкции выше. Одно обновление HACS не извлекает секреты из старого
прибора. Частные тихие сборки, Lite с внешним MCU и другие модели не заменяются
публичной Lite-прошивкой автоматически. На одном приборе проверены обновление от аккумулятора, реальные сенсоры,
сохранение настроек и автоматический подхват HA. Физический перенос между
двумя серверами HA пока не проверялся.

### Простые версии прошивок

У каждого совместимого аппаратного профиля свои **1, 2, 3…**. Версия HACS и
общего GitHub-релиза отдельная. Точный build ID и возрастающий OTA revision
сохраняются для проверки; старый прибор не переименовывается и не
перепрошивается только ради короткой надписи. Lite 1 прошла аппаратную
проверку; отдельные полные комплекты Monitor 1 S8/SCD40 1 ещё готовятся.
Границы готовности и выпусков
описаны в [контракте](docs/FIRMWARE_VERSIONING.md).

Выбрана только полная ESPHome для Lite, Monitor 1 и Monitor 2. Bridge Monitor 1
остаётся внутренней частью установки/восстановления, не урезанным продуктом.
Неизвестный или незаконченный порт не становится пригодным к установке от
одного номера. Выключение вентилятора можно отложить до версии 2, если обычные
измерения, экран и работа с HA уже готовы; ограничение указывается явно.

### Выпуск прошивки

Работайте с чистым committed snapshot. Подготовьте публичный шаблон через
`tools/prepare_release_template.py`, затем упакуйте интеграцию. При изменении
прошивки увеличьте ревизию профиля в `firmware/releases.json` и версию native
UI вместе. Builder проверяет наличие версии в соответствующем BIN. Частные
опыты с вентилятором не входят в публичную production-прошивку.
Ревизия API профиля берётся из тех же release metadata. Опубликованные
BIN/манифест повторно используются только при совпадении
`release_source_sha256` с текущими входами прошивки. Изменение исходников под
прежней версией блокирует новый образ с другим timestamp. После первой сборки
запустите `tools/check_profile_wire.py`: он проверяет совместимость настоящего
C++ шифрования прошивки с Python-декодером.

`python tools/build_firmware_catalog.py --tag vX.Y.Z --check-previous` создаёт
каталог, публичный BIN и исходный манифест в новом каталоге
`.build/firmware-release/vX.Y.Z/`. Релиз только установщика сохраняет предыдущую
запись прошивки и её неизменяемые ссылки. Workflow стабильного тега публикует
три файла рядом с HACS ZIP. Prerelease не становится стабильным каталогом;
существующие файлы релиза не перезаписываются.

## Структура и разработка

- `custom_components/qingping_esphome/` — HACS-интеграция и локальная панель
- `ports/lite/` — ESP32 UI25 и закреплённая среда сборки
- `ports/monitor1/` — Linux host-порт CGS1, S8/SCD40 и guard-компоненты
- `ports/monitor2/` — статус и требования отдельного порта
- `tools/build_lite.py` — сборка публичного шаблона без персональных данных
- `tests/` — проверки app/CRC, допуска профилей и однократной MQTT-команды

```sh
python -m venv .venv
.venv/bin/pip install -r ports/lite/requirements.txt
.venv/bin/python tools/build_lite.py
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/package_release.py
```

Релизный ZIP появляется в `.build/`. Не распространяйте персональные BIN/ELF,
`secrets.yaml`, backup, логи и private device profiles. Это неофициальный проект,
не связанный с Qingping, Xiaomi или ESPHome.

### Прошивка Lite в v0.1.3

Пересобранный шаблон сохраняет GPIO13 HIGH при PM OFF, чтобы не прерывать связь
с CO₂. PM OFF останавливает опрос и делает показания PM недоступными;
вентилятор продолжает работать. Обновление HACS меняет только установщик:
уже прошитые ESPHome приборы автоматически не перепрошиваются.

### Прошивка Lite 2

Direct-I2C профиль добавляет тихий PM-режим с защитами и согласованный OLED
интерфейс: контурные/классические цифры, заставки с часами и датой, общие
настройки на приборе и в HA, плавные переходы, полное гашение ночью и два
подтверждения другого слота. При ошибке защита возвращает HIGH ради измерений;
в этом состоянии вентилятор может включиться. [Подробные границы](ports/lite/README.md).
Native обновление сохраняет исходную stock 4.3.4/4.5.8 и существующий HA-источник
для экрана. Первичный Bluetooth-мастер остаётся только для4.5.8/HW0001;
внешний MCU – отдельный неподготовленный профиль. Для новых полей
персонализации нужна интеграция0.2.1. Обнаружение само не запускает OTA.
