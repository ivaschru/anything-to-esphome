# Lite / CGDN1, stock 4.2.1: порт в разработке

**Готового образа ESPHome пока нет.** В мастере этот вариант распознаётся
отдельно, но установка заблокирована. Образ `ports/lite/` для stock 4.5.8
ему не подходит. Статус обновлён 10.11.2026.

В исследованном экземпляре 4.2.1 измерения обслуживает внешний MCU,
связанный с ESP32 по UART1: 115200, 8N1, TX GPIO18 / RX GPIO19.
Имеющийся порт 4.5.8 работает с сенсорами напрямую через I²C и удерживает
GPIO18 в HIGH при старте. Совпадение CGDN1 / HW 0001 не устраняет это различие.
Простое добавление версии в whitelist не даст работающие сенсоры.

## Что уже подготовлено

`protocol.h` сохраняет прежний API и использует общий переносимый receive-only
C++ разборщик CG/TLV из [MCU backend](../lite-mcu4x/README.md).
Он проверяет длины, magic, сумму и границы каждого TLV, ограничивает память
и количество записей. Вход может быть бинарным кадром либо ASCII hex
аргументом `hex_string`. Ошибка очищает результат, чтобы прежний кадр нельзя
было принять за новый. Неизвестные и повторные ключи сохраняются без
интерпретации. Код не открывает UART, не управляет GPIO и не отправляет команды.

Формат установлен по сохранённому приложению stock 4.2.1:

```
43 47 | command:u8 | payload_length:u16LE | payload | sum:u16LE
TLV: key:u8 | length:u16LE | value
```

Суммируются все байты до checksum modulo 65536. Полный размер — payload + 7.
Stock ESP32 передаёт исходящие кадры как ASCII hex после `hex_string `.
В новом backend реализованы обрамление строк, bounded UART receiver и
независимый срок свежести raw-полей. Startup, физические шкалы и рабочий
lifecycle по-прежнему требуют подтверждения для exact MCU.

## Проверенные точки протокола

| TLV | Назначение в исследованном stock | Что ещё требует проверки |
| --- | --- | --- |
| 0x02 | Два 16-битных поля T/RH, затем stock-компенсация | Масштабы, компенсация, invalid values |
| 0x05 | Ёмкость батареи, 8 бит | Единицы и invalid values |
| 0x06 | Напряжение батареи, 16 бит | Единицы и invalid values |
| 0x07 | Состояние батареи, 8 бит | Таблица состояний / USB |
| 0x08 | CO₂, 16 бит на проводе reference MCU 0354 | Масштаб, invalid values, возраст отчёта |
| 0x0a / 0x0b | PM2.5 / PM10, 16 бит на проводе reference MCU 0354 | Масштабы и invalid values |
| 0x24 → 0x25 | PM interval request → ACK | Физическая семантика 0 и работа от USB |

Поле command внешнего CG кадра и TLV key — разные уровни. Публичная
[таблица MQTT Qingping](https://developer.qingping.co/private/communication-protocols/public-mqtt-hex)
использует похожее обрамление, но другие назначения ключей. Её нельзя
подставлять в этот UART-драйвер. ACK интервала не доказывает остановку PM.
Четырёхбайтовое поле ESP32 RAM не доказывает четырёхбайтовую длину TLV:
MCU 0354 формирует CO₂/PM как два байта. Несовпадение длины на другом MCU
остаётся ошибкой схемы, его нельзя скрывать дополнением нулями.

## Что нужно до образа для ручной установки

1. Восстановить startup, heartbeat, ACK и окончания строк serial-команд.
2. Подтвердить GPIO удержания питания, дисплея и ввода именно этого варианта.
   Не переносить ранний power latch / PM GPIO из 4.5.8 без доказательств.
3. Восстановить единицы, invalid values и правила свежести измерений.
4. Подключить эти данные к отдельному ESPHome backend и собрать отдельный
   public template. Старый образ нельзя выдавать под новым именем.

Дальнейший источник — сохранённое приложение, точные публичные исходники
этой ревизии либо пассивная запись обмена ESP32↔MCU при штатном запуске.
Последняя потребует отдельной аппаратной процедуры; мастер её не выполняет.
MCU update image полезен для разбора PM OFF, но его отсутствие само по себе
не доказывает невозможность обычного чтения сенсоров. Нельзя требовать
обновления/стирания MCU только ради получения файла.

## Основание и границы проверки

Исследована приватная копия ESP32 app 4.2.1, 1 810 048 байт, SHA-256
`feb78216a1a1477036672a736d1e8a0d104f8c23bb6b128ee7f1a89a731ab5d5`.
В public нет самого app, дампа, домашних идентификаторов или журналов.
Проверяемые адреса: CG parser `0x400e2240`, builder `0x400e2454`,
dispatcher `0x400d6d90`, T/RH `0x400d6f36`, UART init `0x401717c9`,
emitter `0x400d6430`, строковая обёртка `0x400d6bcf..0x400d6c42`.
При разборе от точных входов учитываются literal pools Xtensa.

Тесты используют синтетические пакеты, включая известную сумму, повреждённые
и обрезанные кадры, переполнение суммы, пределы TLV и 20 000 случайных входов
под ASan/UBSan. Это проверка парсера на компьютере, а не испытание драйвера
на приборе. Реальная трасса UART пока не использовалась.

```sh
mkdir -p .build
c++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined -fno-omit-frame-pointer tests/test_mcu421.cpp -o .build/test_mcu421
.build/test_mcu421
QINGPING_TEST_PYTHON=.venv/bin/python node tests/test_compatibility.mjs
```
